## 1. 现有实验需要先澄清的事实

### 提示词已经要求答案标签

`data/generate.py` 和已保存的 `data/{train,validation,test}.jsonl` 均包含：

```text
Return the final integer in <answer>...</answer>.
```

原始 128 条训练题、32 条验证题、48 条测试题全部要求该格式。`src/evaluate.py` 将这些题目作为 user message 输入模型，并关闭 thinking mode。

`src/verifier.py` 接受标签、boxed 或独立最终数值来判答案；格式错误率单独统计标签是否合规。`src/train.py` 的奖励仅调用数值 `score`，没有单独的格式奖励。因此，当前事实支持“要求了格式，但模型没有遵循；数值奖励也没有直接区分正确答案的两种格式”。它不能说明模型输出乱码或无法提取答案。

### SFT 出现任务表现塌陷，成因还没有被对照实验确定

输入题型相近，不代表训练目标对应的回答行为相近。Answer-only SFT 把约 200-token 的原始分步解答改成直接生成答案标签和整数。训练后的测试回答平均只有 9.52 tokens，而算术准确率为零、标签合规率为 100%。

这支持“生成策略被强烈改变”的解释，尚不能证明算术能力被完全抹除。答案监督也并非必然导致失败。当前日志显示，answer-only SFT 的逐步 loss 从 5.2562 降到 0.8583，没有记录到 NaN；这是生成效果退化，不能直接归为数值训练发散。学习率 1e-4、128 条数据、32 次更新和目标形式的影响尚未分开。

建议保留相同题目，比较以下控制变量：

1. 仅最终答案。
2. 程序校验的短步骤和最终答案。
3. 保留基座正确解答的主要计算过程，仅规范最终答案格式；这些过程也需要检查。

先固定学习率比较目标形式，再对选定形式比较学习率 1e-5、3e-5、1e-4，并在第 4、8、16、32 步保存诊断 checkpoint。分别检查训练题和验证题的数值正确率、格式合规率、回答长度，以及答案数字部分的 loss。训练题也不会，意味着尚未学好目标；训练题会而验证题不会，才更支持过拟合或泛化失败。上述对照主要用于定位原因，不直接作为新项目最终训练方案。

### GRPO 的有效题目组很少

以下数值来自 `runs/*/metrics.jsonl` 中包含逐步 reward 的记录；排除末尾仅含训练汇总的记录。原来的部分文档均值与原始逐步日志不一致，本方案采用重算值。

| Run | 更新次数 | 每步题目数 × 每题回答数 | 总题目组数 | 零奖励方差组 | 含正负奖励的组 |
|---|---:|---|---:|---:|---:|
| 直接 GRPO group 4 | 20 | 2 × 4 | 40 | 26（65%） | 14 |
| 扩展 GRPO group 4 | 40 | 2 × 4 | 80 | 52（65%） | 28 |
| Trace SFT → GRPO | 20 | 2 × 4 | 40 | 32（80%） | 8 |

同一题四次全对或全错时，组内中心化奖励为零，正确性部分不提供策略梯度；KL 项仍可能产生更新。20 步并没有让 group-4 模型遍历 128 道训练题，只产生了 40 次题目组暴露。整体平均 reward 在中间，也不保证每道题都有混合正负样本。

训练只看最终答案、样本高度相关、训练表达式与测试文字题的差异，以及单种子小测试集，进一步限制了结论。当前证据没有确定“KL 太强”或“模型无法学会”；很小的 KL 也可能来自更新量小、有效奖励组少等原因。

## 2. 可以选择的项目方向

| 方向 | 核心问题 | 新增工作 | 适用目标 |
|---|---|---|---|
| 可验证数学 RL 实验平台 | 难度筛选和动态采样是否提高单位训练预算的收益？ | 数据生成、验证器、GRPO、对照评测 | 侧重后训练算法实验 |
| 预算约束的工具数学求解器（推荐） | 小模型能否学会何时计算、何时调用工具、何时纠错？ | 多轮轨迹、工具执行、SFT、RL、成本评测 | 同时展示模型训练和系统工程 |
| 可校验步骤与推理时搜索 | 检查步骤是否比增加采样更有效？ | 结构化步骤、验证器、候选选择、搜索 | 侧重推理和验证机制 |

推荐以第二个方向为主线，先做可靠的单轮数学 RL，再扩展工具交互。课程学习和动态采样作为有对照的实验因素加入，避免第一版同时改变所有组件。

项目建议名称：**预算约束下的可验证数学推理：工具学习与强化学习**。

### 候选研究问题和判断依据

主问题：在同一个 7B 模型、相同工具权限和固定总生成 token 预算下，工具轨迹 SFT 后的 GRPO 是否改善未见数学题上的最终答案准确率？若没有改善，增加工具或多数投票能否以更低成本达到同样效果？

候选假设 H1：从产生非零组内奖励差异的题目组学习，相比静态随机题目采样，能改善单位 rollout token 的准确率收益。候选假设 H2：在正确性稳定后优化调用和生成成本，能够改变准确率与成本的折中。这些是假设，当前没有本项目结果支持。

自变量是训练策略或单项采样机制；主要因变量是固定推理预算下的单次最终答案准确率，次要指标是成本、pass@4、格式和恢复行为。固定基座 revision、题目池、工具权限、采样参数和测试题，分别记录训练种子与推理种子。训练成本与推理成本分开报告，量化/精度发生变化时另列对照。

主要比较是 D 对 C，随后 E 对 D，使用相同测试题的配对准确率差与区间，不把测试集上挑出的最好结果当作预先选定策略。题数先根据 pilot 的配对错误分布估计；三个训练种子只覆盖部分训练波动，不保证能识别很小的收益。实际有用的差异阈值、预算和最终配置应在最终测试前固定。由于当前是候选计划，尚无新训练入口命令、依赖锁文件或实测超时，不能把现有单轮命令当作新系统可运行的入口。

## 3. 怎样让题目真正更复杂

复杂度来自选择数学方法、建立模型、处理约束或构造解证据。仅放大整数范围主要增加计算量。

| 题族 | 示例 | Gold 与验证方式 |
|---|---|---|
| 约束计数 | 从 1 到 30 选 6 个数，任意两数不相邻，且总和能被 7 整除，有多少种选法？ | DP 或独立穷举；此例程序穷举得到 25300 |
| 条件概率 | 多颜色球不放回抽样，在给定事件成立时求另一事件的概率 | 精确组合计数和有理数 |
| 代数与参数 | 带定义域、整数性或参数条件的方程、递推式 | 符号运算，加定义域及代入检查 |
| 数论 | 同余约束、整除计数、递推模运算 | 独立程序求解与校验 |
| 有证据的优化 | 带互斥或前置约束的背包问题，同时输出最优值和物品集合 | 检查可行解，另用精确算法计算最优值 |

第一版优先做三类可精确求解题族，每类包含多个生成规则。按生成规则或约束组合划分训练与测试，而不仅仅换随机数。新题在独立随机种子下生成，并检查重复、可解性、题意和 gold。

使用模型预采样校准难度。每题先采样 4–8 条，用实测成功率分层；成功率约 20%–80% 可作为起始筛选启发式，不视为算法保证。保留全对和全错题的统计，不把它们从评测集中删除。全错题先通过更容易的课程、合格示范或增加有限采样预算处理。

公开题用于补充自然语言多样性与外部评测。可从 DeepScaleR 的问题答案对中筛选训练题，MATH-500 留作最终外部评测；先检查与验证/测试题的来源及重复关系。公开参考解答不自动等于经过验证的训练轨迹。MATH-500 包含符号、元组等答案，不能继续只用当前整数解析器；任何子集评测应明确题数和筛选条件。公开题也不能证明基座预训练没有见过，因此需要新生成的结构隔离测试集一起报告。

## 4. 求解器的行为和训练方式

```text
读取题目
  → 选择直接推理或调用 Python / SymPy
  → 获取工具结果或错误
  → 必要时修改计算方法
  → 输出最终答案；可构造证据的任务同时输出证据
```

工具运行在独立受限进程中，限制时间、内存、输出和访问范围。轨迹完整记录 assistant 动作、工具输入、工具结果和最终答案。模型和工具都不接触 gold。

SFT 只监督 assistant 生成的部分。多轮 RL 也只对模型动作计算策略概率，工具返回值不作为模型生成的 token 计算策略梯度。工具报错恢复、轮次上限、截断处理和轨迹回放都是需要实现的工程内容，现有单轮 `train.py` 需要扩展。

先以正确性为主要奖励，格式单独统计。工具调用本身不给正奖励，避免模型通过无意义调用得分。成本优化在正确性学习稳定后加入，比较同样准确率下的 token 和调用开销；若使用标量成本奖励，应保持所有正确轨迹的奖励高于错误轨迹，并单独消融。

验证器需要说明边界：等式成立不等于解题逻辑完整，代码能运行不等于建模正确。自然语言证明暂不声称可自动完整验证。约束解、精确数值和符号结果应分别使用适当检查器；符号等价需考虑定义域，不能把任意表达式的 simplify 结果当作普遍证明。

## 5. 核心对照实验

| 编号 | 配置 | 回答的问题 |
|---|---|---|
| A | 基座，纯推理 | 当前能力起点 |
| B | 基座，提供同样工具与示例 | 工具接入本身的收益 |
| C | 经过校验轨迹的 SFT，提供工具 | 学习解题与交互轨迹的收益 |
| D | C + 普通 GRPO | 在线奖励更新的增量收益 |
| E | D + 动态采样 | 单位训练预算下有效题目组是否增加 |
| F | 选定策略 + 成本目标 | 能否在保留准确率时减少开销 |

D/E 保持任务池和推理预算一致，并记录动态采样中被丢弃回答消耗的 token 和时间。只比较相同步数会忽略额外采样成本。动态采样可以借鉴 DAPO，但本项目的单项实验不能称为完整复现 DAPO。

基座和 SFT 另做同样预算的多数投票基线，帮助判断 RL 收益是否超过简单增加采样。工具权限、总生成 token 和最多交互次数保持可比；吞吐与工具 CPU 时间另外报告。

pass@4 是用 gold 事后计算的候选成功率。它不能代表系统在线一定选到了正确候选。实际答案选择采用多数投票或独立可验证的解证据；读取 gold 的答案 verifier 仅用于训练奖励和离线评测。

最终报告包括：

- 单次回答准确率、跨样本平均单次准确率、pass@4 和多数投票准确率，清楚说明计算方式。
- 格式合规率、工具执行成功率，以及适用任务上的解证据有效率。
- 生成 token、工具次数、延迟、GPU 小时和峰值显存。
- 各题族与难度层的表现、奖励零方差组比例、截断比例和错误类别。
- 选定配置的三个训练种子，以及按题目重采样的配对置信区间；二者反映不同的不确定性。

## 6. 5090 的起始资源方案

| 项目 | 起始方案 |
|---|---|
| GPU | 单张标准 RTX 5090，32GB；实际型号显存不同则调整 |
| 小规模调试 | 保留已有 1.7B 模型，用于验证数据与轨迹实现 |
| 主实验 | 建议 Qwen/Qwen2.5-Math-7B-Instruct，锁定该模型自己的 revision 和 chat template |
| 微调 | 优先 QLoRA：4-bit NF4 基座、BF16 计算、可训练 LoRA adapter；记录双重量化等实际配置 |
| 内存管理 | 梯度检查点、小训练 microbatch、梯度累积；尽量复用基座并切换冻结参考 adapter |
| 初始采样 | 每题 4 条轨迹，逐步增加每次更新的题目数 |
| 训练 microbatch | 先从每次前向/反向 1–2 条轨迹测量，以梯度累积形成有效 batch；题目组采样数和训练 microbatch 分别配置 |
| 初始长度 | 轨迹总生成上限 1024–2048 tokens，最多 2 次工具调用；根据截断统计再扩展 |
| 试验数据 | 先 500–1000 题校准难度；首轮训练池 3000–10000 题 |
| SFT 示范 | 先收集 500–2000 条合格轨迹；不要求每道题都能生成示范 |
| RL 预算 | 先 30–50 步测吞吐与信号，再制定约 200–500 步的候选实验预算 |

以上是待测起点，不是显存或收益保证。7B 级模型的 BF16 权重本身约 14–16GB，激活、KV cache、参考策略和运行时还会占显存；4-bit 模型也有未量化参数和量化元数据，不能按参数量乘半字节直接当作总训练显存。单卡首版分阶段加载训练与推理资源，参考策略尽量使用共享冻结基座及冻结 adapter，避免额外常驻完整模型副本；独立 rollout 服务的额外模型和缓存占用需要单独测量。用测到的每轨迹长度、每步耗时和重采样开销估算 GPU 小时，再决定训练规模。

选择 Math-7B-Instruct 的依据是官方明确支持中英文数学的 CoT 与工具集成推理（TIR），适合先建立可用工具基线，再研究后训练增益。它已经经过数学指令训练，因此必须保留“原始 Math-7B-Instruct 加同样工具”的强基线；不能把已有工具能力算作本项目训练收益。QLoRA 的主要比较先统一基座量化配置，再单列 BF16/4-bit 对照以识别量化影响。更换模型后重新测量题目难度，不能沿用 1.7B 的成功率分层。该模型的提示模板不使用 Qwen3 的 thinking 开关，迁移时需核对模板、结束 token、上下文长度和依赖兼容性。

工具错误恢复可以作为后续受控实验：比较仅成功示范与包含真实报错后修复的示范，控制示范 token 总量，并在独立错误条件下评测最终成功率。它会引入额外训练因素，先完成主实验再决定是否加入。

### 与已有工作的关系

- [ReTool v2](https://arxiv.org/abs/2504.11536v2) 已研究自然语言推理与实时代码执行交替、多轮工具 rollout 和基于结果的 RL。本项目借鉴这条路线；“用了工具和 RL”本身不构成方法创新，32B 的论文结果也不能外推为本项目 7B 的预期收益。
- [DAPO v2](https://arxiv.org/abs/2503.14476v2) 提出动态采样等训练机制。本项目可以研究其中单项机制在单卡、小模型和固定采样预算下的效果，不能用一个开关代表完整 DAPO。
- [s1 v3](https://arxiv.org/abs/2501.19393v3) 研究训练示范和推理时预算控制，提醒本项目需要把增加推理计算与改变训练算法的效果分开；本方案不假设其 32B 结果会在 7B 上复现。

当前做的是针对方案的资料检索与证据对应，并未完成系统性文献综述或新颖性审查。可交付价值首先是单卡可复现实现，以及对训练、工具、采样和预算收益的可信测量。

## 7. 实施顺序与交付物

1. **修订旧实验口径**：保存统一重算的指标，区分最终答案、格式和过程；补足 SFT 原因的最小对照实验。
2. **做可靠数据与基线**：三个题族、精确 gold、结构隔离切分、基座纯推理和工具基线、难度分层报告。
3. **做轨迹 SFT**：保存完整动作与工具结果，验证 mask 和回放；比较格式与正确性是否同时保留。
4. **做单因素 RL 对照**：普通 GRPO 对动态采样，先固定正确性奖励与工具预算，记录所有采样成本。
5. **做预算与泛化分析**：选定配置重复种子，在新生成测试题及外部测试上评测，并交付错误分析与可复现命令。

可展示成果是数据生成与验证器、可回放的工具轨迹、训练 adapter、统一评测记录、预算收益曲线和对照实验报告。项目价值取决于能否可信地回答训练和计算预算带来的增量收益，不预设最后一定是 RL 胜出。
